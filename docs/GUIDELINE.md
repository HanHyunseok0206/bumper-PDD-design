# 프로젝트 개요

종합설계(졸업연구) 프로젝트. 제목: "PDD 기반의 surrogate modeling을 이용한 범퍼 강건 설계".

- 카티아로 3D 범퍼 형상을 설계하고, 아바쿠스(Abaqus/Explicit)로 충돌 FE 해석해서 SEA(비에너지흡수율)를 얻고, 그 데이터로 서로게이트를 만들어 강건 최적 설계를 진행하는 흐름.
- SEA(비에너지흡수율=흡수에너지/질량)는 최대화가 목표, "강건"은 그 값이 불확실성 변수(재료 물성 편차, 두께 공차, 충돌 조건 등) 아래에서도 흔들리지 않게 하는 것 — 서로 다른 두 축을 합쳐 목적함수는 `maximize mean(SEA) - κ·std(SEA)` 형태로 둠. 다목적(PCF·질량 등 제약 포함 여부)은 최종적으로 지도교수/선행연구 formulation 확인 필요.
- **PDD의 역할(지도교수 지침, 2026-08-27)**: 범퍼 충돌 응답은 좌굴모드 전환 등으로 비선형·불연속적이라 PDD 같은 전역 다항식 서로게이트는 예측 정확도에 한계가 있을 수 있음. 그래서 PDD는 **민감도 분석(변수 스크리닝)** 용도로 쓰고, 실제 최적화에 쓰는 **서로게이트는 크리깅(Kriging)**으로 구축. 논문 제목("PDD 기반의 surrogate modeling")은 한 번 정하면 못 바꾸므로, "PDD 기반 민감도 분석 → 변수 선별 → 크리깅 서로게이트 구축"이라는 전체 파이프라인 자체가 "PDD 기반"이라는 논리로 방어(옵션 A). 시간 여유되면 PDD 예측을 크리깅의 트렌드 함수로 넣고 크리깅이 잔차만 학습하는 하이브리드(옵션 B, PDD가 최종 서로게이트에 문자 그대로 포함됨)로 업그레이드 — A의 결과물(DOE 데이터, PDD 계수, 초기 크리깅)이 B의 재료가 되므로 순서상 자연스러운 확장.
- 저장소: https://github.com/HanHyunseok0206/bumper-PDD-design

# 연구 진행 방향 (카티아 + 아바쿠스 파이프라인, 2026-08-27 갱신)

0. **설계변수 정의**: 카티아에서 바꿀 파라미터(두께, 리브 위치, 곡률 등)와 LB/UB 확정, 외부에서 구동 가능하게 설정(Design Table 또는 매크로)
1. **DOE 샘플링** (`DOE_sampling.ipynb`, 파이프라인에서 제일 먼저 실행): LHS로 설계공간에서 N개 점 추출 (변수 수의 8~10배 정도로 시작). FE가 병목이니 한 번에 다 뽑지 말고 예를 들어 50개로 먼저 시작 → 부족하면 추가(11단계 순차 보강과 같은 원리를 DOE 단계에도 적용). 설계변수뿐 아니라 불확실성 변수(재료 물성 등 random/uncertain variable — "노이즈"라고 부르지 않음)도 같이 흔들어서 뽑아야 함 — `doe_points.csv`로 저장해 카티아/아바쿠스에 전달
2. **형상 자동 생성(카티아)**: DOE 점마다 매크로로 형상 생성 → FE용으로 export. 점이 많아지므로 자동화 필수
3. **FE 해석(아바쿠스)**: Abaqus/Explicit 충돌 해석. Abaqus Python 스크립팅으로 job 생성·제출·모니터링 자동화. **계산 비용 관리**: (a) 여러 job을 동시에 제출할 수 있는지(랩 서버/클러스터, 라이선스 개수) 확인 — 병렬화가 전체 일정에 제일 큰 영향을 줌. (b) 민감도 스크리닝(6단계)용 초기 DOE는 거친 메시(빠른 해석)로 돌리고, 크리깅 최종 검증/최적점 확인용 소수 점만 정밀 메시로 재해석하는 저비용-고비용 혼합 전략 고려. 이건 워크숍 자료의 다중충실도(Multi-Fidelity, `Lab3_MFMC`/`Lab4_Plate_MF`) 방법론과 같은 발상이지만, 지금은 그 정식 통계적 결합(상관계수 기반 최적 배분 등)까지는 안 쓰고 "초기엔 싸게, 나중엔 비싸게"라는 실무적 요령 수준으로만 적용 — 시간 남으면 MFMC처럼 저충실도·고충실도 데이터를 하나의 서로게이트로 정식 결합하는 것도 고려 가능.

  **참고(개념 구분)**: 다중충실도(메시 거칠기 등 시뮬레이션 자체의 정밀도 축)와 서로게이트 모델링(PDD/크리깅처럼 시뮬레이션 결과를 통계적으로 근사하는 축)은 둘 다 "비싼 것 대신 싼 것을 쓴다"는 발상은 같지만 서로 다른 축이라 "다중충실도 안에 다중충실도"가 아니라 **독립적으로 조합 가능한 두 개의 절약 수단**임. (지금 파이프라인 = 단일 충실도 FE + 서로게이트만 사용. 위에서 말한 혼합 메시 전략까지 더하면 두 축을 함께 쓰는 것.)
4. **결과 추출**: `.odb`에서 odbAccess로 흡수에너지·반력(PCF)·질량 추출, `SEA = 흡수에너지/질량` 계산
5. **데이터셋 조립**: `X`(dim × N) = 설계변수, `Y`(N,) = SEA → `PDD_bumper_SEA.ipynb`의 데이터 로딩 자리에 투입
6. **PDD 민감도 스크리닝**: `find_optimal_degree` → PDD 적합 → `get_sobol2`로 변수별 기여도 확인, 기여도 낮은 변수는 명목값 고정, `DESIGN_IDX`/`NOISE_IDX`(불확실성 변수) 결정
7. **크리깅 서로게이트 구축**: 같은 DOE 데이터(또는 스크리닝 후 축소된 변수)로 크리깅 학습, 홀드아웃/교차검증 R²로 정확도 확인(학습 R²만 믿지 않기)
8. **(옵션 B, 스트레치) PDD-트렌드 하이브리드**: `residual = SEA_true - PDD예측` → 그 residual에 크리깅 적합, 최종예측 = `PDD(x) + Kriging_residual(x)`. 순수 크리깅(7) vs 하이브리드(8) 정확도 비교
9. **강건 목적함수**: 최종 서로게이트로 `estimate_robust_sea(d)` — 설계값 고정, `NOISE_IDX` 변수만 흔들어 mean/std 계산. `J(x) = mean(SEA) - κ·std(SEA)`, κ는 0~3 스윕
10. **최적화**: `scipy.optimize`로 `DESIGN_IDX`에 대해 `J(x)` 최대화, 질량/PCF 등 제약 반영
11. **검증**: 최적점을 카티아로 재형상화 → 아바쿠스 재해석 → 서로게이트 예측과 비교, 오차 크면 DOE에 추가 후 6~7단계 재적합(순차 보강)
12. **정리**: 민감도 분석 결과, PDD vs 크리깅 vs 하이브리드 정확도 비교, κ별 강건-결정론적 최적 설계 트레이드오프가 논문 핵심 결과

2~3번(카티아/아바쿠스 자동화)이 준비 안 되면 가장 시간이 많이 드는 구간이라 우선순위 높게 챙길 것.

## 완주 우선순위 (MoSCoW, 2026-08-27)

목표: 완주(반드시 끝내기)와 우수상(눈에 띄는 기여) 둘 다 욕심내다가 둘 다 놓치는 걸 방지. **완주를 먼저 깔고, 그 위에 싼 값에 얻을 수 있는 것부터 순서대로 얹는다.**

**반드시(MUST) — 이거 없으면 논문 자체가 성립 안 됨, 절대 타협 안 함**
1. 설계변수·재질 확정
2. 카티아·아바쿠스 자동화 (완벽할 필요 없음, 반복 가능한 수준이면 충분)
3. DOE 실행 → 실데이터 확보 (파이프라인 0~5단계)
4. PDD 민감도 스크리닝 — 실데이터 (6단계)
5. 크리깅 서로게이트 학습+검증 — 실데이터 (7단계)
6. 강건 목적함수 구성 + 최적화 (9~10단계)
7. 최적점 최소 1회 재해석으로 검증 (11단계)
8. PAPER.md 결과(4장)·결론(5장) 채우기

**되도록(SHOULD) — 비용 거의 안 드는데 효과 큼, MUST 끝나면 거의 자동으로 딸려옴**
- PDD vs 크리깅 비교를 실데이터로 재현 (기존 코드·데이터 재사용, 추가 FE 불필요) → PAPER.md 3.5절 갱신
- κ 스윕 결과를 mean-std 트레이드오프 그래프로 정리 (10단계에서 이미 나오는 숫자를 시각화만 하면 됨)

**여유되면(COULD) — 우수상 노릴 때 진짜 도움 되는 것**
- 능동학습 (FE 절약 효과를 정량적 숫자로 제시)
- 베이지안 최적화

**접기(WON'T) — 지금은 손대지 않음**
- 물리 시제품 제작·시험, 딥러닝/생성형 설계, 다중충실도 BO, SAEA

**판단 규칙(날짜 대신 체크포인트 기준)**: MUST의 6번(최적화)까지 끝난 시점에 마감까지 여유가 있으면 SHOULD 진행 → 그래도 여유 있으면 COULD 하나 시도. MUST가 마감 임박해서도 안 끝나 있으면 SHOULD/COULD 전부 버리고 MUST 완주에만 집중.

## 지도교수 피드백 반영 (2026-10-13 미팅)

- **용어 정정**: "노이즈 변수" → "불확실성 변수"로 통일(위 "이 저장소에서 작업할 때" 항목 참고).
- **설계변수 vs 불확실성 변수 경계 재검토**: 지금 "설계변수 범위"(B1~C8 ~6.6~13%)로 다루는 것이 실은 형상을 의도적으로 바꾸는 치수 변경이 아니라 제조 공차 수준의 변동이라, 지도교수는 이것도 "불확실성 변수"로 봐야 하는 것 아니냐고 지적함. 지도교수 결론: "공차에 따른 민감도가 없으면 안 봐도 되니, 지금처럼 변수(민감도 분석 대상)에 물성+공차를 같이 반영해서 보면 된다" — 즉 현재 방식(공차 폭을 설계변수 범위로 취급해 민감도 분석 대상에 포함)은 그대로 유지해도 된다고 확인받음. 다만 "설계변수"라는 이름 자체가 치수 변경을 뜻하는지 공차 변동을 뜻하는지 팀 내에서 안 섞이게 PAPER.md에서 용어를 명확히 정의할 것(후속 과제).
- **재료 물성(U1~U3) 실제 범위(min/max) 기록 필요**: 미팅에서 "범위를 얼마로 잡았는지 기록 안 했다"고 지적받음 — 다음 미팅 전에 기록해서 가져가기로 함(담당: 한현석, 팀원에게 재확인).
- **PDD 결과표 표기 정정**: `n`/`y` 대신 기존 논문 표기 `m`(차수)/`S`(상호작용 차수)로 통일 + Case별 설계변수/불확실성 변수 개수 분리 명시 — `pdd_case_summary_20261016.py` → `pdd_case_summary_20261016.pdf`로 Case 1~6 정리 완료(아래 체크리스트 참고).
- **미해결 질문 — 불확실성 변수 추가 후 PDD 차수(m)가 오히려 낮아진 이유**: Case 3(설계변수만, m=6) → Case 4(불확실성 변수 추가, m=5)로 낮아진 것에 대해 지도교수가 "왜 늘어나야 할 것 같은데 줄었나" 의문 제기, 아직 답변 못함 — 다음 미팅 전 설명 준비 필요. (가설: `find_optimal_degree`의 patience 기반 조기 종료가 변수 수 증가로 k/N이 빡빡해지면서 더 일찍 멈췄을 가능성 — 확인 필요)
- **서로게이트 구축 방향 승인 보류**: "Case 1~5 공통으로 높게 나오는 변수로 서로게이트를 만들 계획, 맞는 방향인가요?"라고 질문했으나 지도교수가 명확히 답하지 않고 다른 주제로 넘어감 — 다음 미팅에서 재질문 필요.
